# 由面试官总控决定对话，可信运行时提交效果

改造前正式链路在理解回答前固定询问补充，execution v2 又在开场前物化全部题目，因此已有语义理解与追问仍表现为固定考试流程。决定保留 InterviewAgentRuntime、Evidence、生命周期和模型网关，在内部增加一个目标驱动的 InterviewerSupervisor：总控基于版本化考察契约、会话记忆、受控工具与按需专家提出下一动作，可信执行器验证并原子提交，只有批准表达可以发声。

自主题目数量与选择需要 execution v3 将每题权重改为冻结能力维度及证据要求，企业 Skill 同样按计划冻结版本；这些变化必须与评分、持久化和恢复一起迁移。相比每轮固定串联多个 Agent 或引入一套独立框架状态库，本方案减少实时模型往返并保留现有单一证据/提交真相；代价是需要明确的新决策合同、覆盖评分验收和有限的 v2 运行期兼容。已有 v2 会话继续原冻结语义，排空后删除其运行 adapter，历史只读保留。

038已实现语义与当题决策、跨题Supervisor、六个工具、受控Skill、v3单元与报告；对外统一运行入口，内部职责分层，未引入外部Agent框架状态库。当前验收范围为仓库回归与本地闭环，真实部署及v2退役另行验收。详细方案和验收见 [面试官 Agent 架构](../interviewer-agent-architecture.md)。

039范围纠正：企业级指Agent运行保障；Skill由用户自由编写且可选，企业资料独立可选。新用户Skill保存即用，不以审批/固定方法模板作为Agent运行前置；保留已选择内容的版本与权限、预算和证据约束。
