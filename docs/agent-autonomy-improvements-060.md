# 面试官自主交流改进与遗漏审查（060）

日期：2026-09-22。工作项：`AGENT-AUTONOMY-060`。承接[059问题与规划](agent-conversation-improvement-plan-059.md)，本轮不增加填写步骤，Skill和企业资料仍然各自可选。实际回归及运行版本以[操作日志](change-log.md)为准。

## 已确认的问题与修复

### 快速回应不能锁住完整理解

轻量接话可能把一句“刚才需要想想，现在讲完了”判断成wait。旧实现随即取消完整理解，并对同一段final持续等待，模型的完整判断没有纠正机会。这是程序裁决缺陷，不能归咎于候选人表达。

wait/continue实际播出后，只登记一份绑定final、输入revision和capture的复核。候选人重新获得话轮且没有新输入时，复用已有准备结果裁决一次：明确说完进入原有完整final与提交校验；明确思考保留等待，不重复安抚；不确定则沿用一次补充确认。新声音、转写修正、失去owner或关闭撤销旧结果。暂停、重读、解释仍沿各自原有路径。等待本身不是提交许可，复核也不产生周期模型轮询。

### 合法回答不应被坏追问提案拖垮

理解已通过，但追问一次写了两问或超过口语长度时，旧实现直接放弃。现在仅对这种可修复提案尝试一次措辞修复：证据、考察目标、理由、难度和安全检查必须先通过；修复模型只可返回是否选中及新问句，不能改写理解、引用或考察范围。

原理解与可选追问共用15秒期限，修复最多占其中3秒。修复失败、超时或模型主动不选，保留已通过的理解；安全、泄题、来源、预算或候选人边界拒绝不靠修复绕过。成功提案仍先生成唯一子题，再播报，回答单独保存。传输合同容纳最多600字符的待检提案，实际批准问句仍最多180字符、至多一个问号；传输可接收不代表可以播出。

相邻审查还发现独立追问的异常备用路径沿用调用前的预算。现在无论模型成功还是失败，返回提案前都重新核对时间、根题预算和话题许可；已关闭即停止，避免依赖最后提交时才拒绝过时提案。

### 长回答也有追问资格

4000字原来同时承担模型输入阈值和业务资格门槛，导致4001字突然不能追问。现在这个阈值只决定调用方式：短回答沿用组合理解与提案；长回答先把完整原文交给理解，再以已验证摘要、主张引用与目标准备可选追问，两步共用原15秒期限。不能截掉末尾的否定、改口、等待或结束意图，也不扩大组合Prompt去堆全文。可选步骤用完期限，保留已验证理解。

### 旧主张按本场来源补查

滚动上下文并不包含所有历史细节。新增`interview.read_context(turn_id)`用法，从当前会话快照读取唯一已提交答案的主张和引用；原来的null参数继续返回有界摘要。最多12条主张，原文引用必须仍在最终答案中；只出现一次时返回字符位置，重复出现时标明次数、位置为空，避免假装定位到某一次发言。

工具不接收组织、外部会话、文件地址或评分查询，不返回完整录音、标准答案或私人评分。总控最多三次模型请求的预算不变。提案指纹新增答案来源哈希，来源更正后旧规划不能提交。它改善的是总控按需回看，不代表每个接话模型拥有全量历史记忆，也不保证模型每次都会主动查旧题。

### 重连提示必须跨后端实例恢复

双Runtime测试发现：原收音通道仍在等待识别重试，新页面连到另一实例时只收到ready，没有等待提示。补齐owner处理同一capture重新open的路径，按当前控制连接代次恢复有效提示；本地attach再open不重复通知，原提示发送失败可重试。识别流和录音继续保留，没有为了刷新UI重开capture或提交空答案。

## 本轮保留并验证的规则

- 正式追问是父题下的独立子题，子回答单独保存；确认语和面试官解释不冒充子题。
- 评分按题目链引用相应回答，父题权重只计一次；不把跑偏的子回答直接拼入父答案。相邻审查未找到新的评分缺陷，不泛改评分规则。
- 所有回答仍来自服务端权威语音转写；临时字幕可能被修正，客户端文本不能形成答案。
- 没有改PCM分片、播放缓冲或媒体时钟。本轮修的是判断、状态和恢复，不能把逻辑测试当作真人听感验收。
