# 078：回答结果复用与有限自动恢复

状态：verified（仓库全量、本机加载；真人长场次与外部环境待验）。实际加载、验证结果以操作日志078为准。

## 现场与目标

截图场次在准备追问成功后，补充回复已被识别为finish，确认后的第二轮完整理解决策在12秒超时，20秒交互期限随后耗尽。它不是已提交追问的TTS故障。另有明确的代码缺陷：补充询问仍处于snapshot阶段执行，表达预算失败可能被误归类为识别恢复，已合成复现；本场snapshot超时与该路径吻合，但缺少完整阶段追踪，不能把推断当作现场已证实根因。“重试处理”又复用continue_speaking撤销了已有确认。“回答啦”被当成技术疑点且实际播出也是独立语义错误。

目标是减少重复模型请求，使偶发可重试故障由系统自动消化。外部服务持续不可用、鉴权或计费失败不无限重试；不新增供应商、备用模型或音色。

## 证据有效才复用

- 在已实际送达的补充询问之后，服务端轻量语义判断新回复为finish；新回复还须通过保守的纯控制语句资格检查。它是复用资格检查，不能独立授权结束回答。
- `PreparedCompletionReceipt`组合原准备结果、原final、询问送达后的回复边界和新回复。原技术文字、分段时间、质量、Provider/model/语言必须保持；未提供可验证分段时回到完整理解，不拼造证据。
- 只复用无未解决歧义的普通答案或清楚跑题答案。真正的新技术补充、转写更正、内容澄清、退出请求、政策或上下文变化均使复用失效。技术证据不会因回复较清楚而提高原质量。
- 新理解只派生结束依据，不补写技术claims。提交再次验证完整final、补充送达事实、来源和当前上下文，并沿原owner/control/capture/生命周期围栏；原有问题选择、评分与实际播放规则不放宽。
- 组合证明为服务端进程内对象，不产生新的客户端授权或持久完成许可。进程重建不能凭页面状态恢复授权。

## 等待时限与调用额度分开

- 正式理解一次执行最多18秒，组合决策外层20秒；网关该调用不另行内部重试或轮换目标。
- 显式单次attempt也约束DashScope的schema→object协议重发。若受限请求收到HTTP400，返回原错误，不能藏在一次网关审计里发送第二个请求；无此限制的已有兼容路径保留。
- 正常交互20秒；首次可重试失败可使用同一交互起点之后最多40秒的恢复窗口，最多两次失败即停止。不是每次失败都重新获得40秒。
- 投机与等待其结果的外层上限统一为20秒。同证据投机失败须在第二次完整调用之前记账并打开上述恢复窗口，避免第二次请求只有原交互剩余几秒。不可重试的供应商错误直接阻断；不能靠新词重新启动无效调用。
- `AnswerProcessingBudget`对同一文本的完整模型调用尝试计数，最多2次。预计算、正式理解、格式纠正及后续模型恢复共用对象；选用独立追问/短句修正时也计入。VAD、重复final及provider请求ID变化不刷新额度。
- 每个capture最多实际发起一次投机模型调用，稳定停顿门槛从1秒调到3秒，投机不再额外纠错重发；正式处理相同证据继承已用次数。它不是“整题无论补充多少次只调用两次”的承诺：新的实质内容需要重新分析。轻量接话/确认和TTS另有原有上限。
- 小型确认/接话分类沿其既有独立上限，不送完整技术答案重新推理。可选追问的原有预算失败规则保留，必须有明确系统原因；已批准追问不会被跳过，模型失败不得记作候选人不会。
- 显式处理重试可以开启新额度，但不会撤销有效确认、重开采集或授权直接提交。继续补充仍表示新发言，按原流程撤销不再有效的准备。

## 分阶段恢复

- 补充询问输出使用独立有界表达期限，不继承已耗尽的理解期限。未送达不能进入“已询问、等待回复”的状态或直接播放二次clarify。
- 自动恢复输出只允许已证明零PCM及精确清理完成、控制权仍有效的原提示；未知/部分播出不透明重放。固定提示复用075同音色缓存，不重复生成完整答案。
- 提示恢复绑定该提示自己的输出checkpoint，送达后清除pending，后续其它输出不能借用旧询问的恢复状态。提交发现准备过期时清除待复用结果，保留仍有效的新确认后重新准备，不反复提交同一旧对象。
- 新`retry_answer_processing`通过durable `evidence.retry_processing`绑定当前turn/capture/owner/control，只恢复已有失败处理。重复命令、活动处理、旧capture、暂停、终态或接管不能启动并发重算。
- 恢复期间保留录音、转写和有效确认，前端显示实际处理阶段；用尽可恢复额度保留显式兜底。明确不可重试错误显示服务暂不可用，不提供无效重试循环。

## 语义与诊断

理解合同版本98–109、组合决策129–140明确普通流程交流不是技术疑点。统一校验拒绝把完整、清楚的开始回答/等待句当作clarification_target；该规则只否决错误提案，不猜测完成意图，不覆盖引用、否定、技术混合句或真实转写争议。错误提案的纠正同样受共享调用额度限制。

`answer_preparation`持久投影包含安全stage/reason_code/attempt/max_attempts/retryable；状态增加blocked。attempt是失败摘要，不是当前供应商请求序号，前端不显示虚假的n/2进度。区分超时、调用额度耗尽、鉴权、计费、限流和熔断，禁止泄露供应商响应正文。新增模型调用尝试、额度耗尽、确认结果复用计数，复用日志不包含候选原话。调用尝试计数不等同成功计费请求，不能据此计算账单余额。没有网络子阶段证据时不声称已区分供应商排队和线路延迟。
