# 065：候选人退出的独立确认

状态：`verified（仓库回归、合成真实模型、本机加载；真人语音及生产未验收）`。本轮取代064中首次明确退出请求即可完成整场的行为；此前交互、媒体及证据修复保留。

## 交互与权限

候选人说“我不想面了”后，面试官先完整播报：

> 你确定要提前结束本次面试吗？确认后将停止本次面试，并记录为候选人主动退出，交由面试安排人复核。

| 候选人后续表现 | 系统行为 |
| --- | --- |
| 明确确认结束整场 | 当前完整权威转写再次校验后，提交退出事实，停止收音与录制，发结束回执 |
| 改口继续 | 保留当前题和完整发言，继续作答；以后再次请求退出仍要重新确认 |
| 静音、嗯、好的、没有、条件句、引用、没听清 | 不授予退出许可；按语义继续等待或再次明确询问 |
| 确认问题播放失败或被打断 | 旧回答不能授权退出，重新完整询问后才接受新的确认 |
| 模型失败、owner/输入变化、final改写 | 撤销或不生成确认许可，保留现有有界重试与失败恢复 |

确认问题独立于“还有补充吗”。首次退出请求内带有“确认”也不能代替问题之后的新回复；按钮结束回答、普通补充确认和旧版本stop_interview记录都不能绕过该流程。

## 模块与来源

`SpokenSupplementConfirmation`维护独立待确认状态，`AnswerEndpoint`在最终提交前统一拦截退出；LiveKit实际agent_finished回执确认问题完整送达。问题仍通过现有批准表达通道播放，当前capture、turn与owner围栏继续有效。等待期间不提交答案、切换题目或清除录音。

`PreparedTurnDecision.exit_confirmation`是服务端私有上下文，包含版本、interview/turn/capture/问题act标识、固定问题、问题播完时已收到的完整转写、新回复、confirm/continue判断和转写SHA256。提交时再次校验同场同题的获批选中act、原文前缀、新回复和完整哈希。确认后出现新词会撤销旧许可；撤回后的上下文保持原回复及原哈希，仅作为历史，不能永久阻止新的退出请求。完整技术证据始终来自原始累计转写。

确认许可只存在当前服务端运行时；重建/接管不从旧文字推断许可，必须重新询问。未新增客户端确认API，候选token和浏览器final无授权能力。

## Prompt与模型约束

新增集中版本`candidate_exit_reply.v1`与固定话术`candidate_exit_confirmation.v1`。回复合同只有intent（confirm/continue/uncertain）、confidence与严格原文evidence_quote；统一Schema及来源校验通过后才交给业务。引用、否定、条件、疑问与改口冲突只能拒绝模型确认，文字规则不能授予确认。

仅含退出上下文的完整理解使用v46–49、组合决策v77–80；原模式版本不变。完整理解须把最新确认视为结束整场，同时保留之前实际技术claims；普通补充确认不能授权退出。独立回复分类走已有interview_turn_understanding路由，8秒、供应商0内部重试；运行时使用原有按输入计数的有界失败预算。未更换供应商或凭据。

## 客观记录与人工复核

确认提交时保存turn级`candidate_exit_confirmation`回执（state、时间、问题act、capture及原文SHA256，不复制原文）；整场保存`candidate_exit_confirmed_at`。原输入结束原因仍为candidate_requested，结束后的评分、媒体清理、刷新/重连使用064生命周期。

报告与企业复核页注明“候选人确认提前退出；待人工复核”。仅旧版本退出记录显示“候选人主动提前退出”，不补造二次确认事实。报告的scope_notice、风险与human_decision_required在统一投影中幂等补充，JSON/CSV导出一致。已评分内容、分数、覆盖率、未考察范围和人工决定保持；不自动归零、补成完整面试或作出录用/淘汰决定。

## 验证与限制

验收包括首次请求不结束、独立确认、撤回继续、新请求、静音与模糊回复、确认未播完/打断、晚到final、控制器替换、重复提交、评分待处理、录制/告别失败、报告与导出。真实模型仅使用虚构发言和内存路由副本，不写业务模型审计或发送真实候选人记录。真人长场次、实际听感、口音弱网与生产依赖仍需独立验收。最终结果及加载证据见[操作日志](change-log.md)。
