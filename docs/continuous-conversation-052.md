# 实时面试交互改造与验证（052）

本轮处理051留下的持续识别、提前准备、串行等待及流式播放问题。目标是候选人继续说话时仍可收音和显示字幕、一般交流能自然回应、语音不用等整段合成完才播放。没有增加面试配置步骤；Skill和企业资料继续独立可选。自动化与本机实测范围见[操作日志](change-log.md)，不代表真人长时或生产多租户验收。

## 当前链路

1. `ContinuousSTT` 保持采集，识别流轮换/恢复期间产生的最新累计字幕不再被丢弃。字幕是展示及撤销信号，不能形成答案。
2. `SpokenSupplementConfirmation` 在稳定预览和短暂停顿后，同时启动一次可撤销的答案预理解与轻量接话。轻量接话直接生成简短口语；普通技术回答不插话，公司反问仍交给有来源的专门路径。
3. `AnswerEndpoint` 只在获取权威final时短暂收口；覆盖已有字幕并投影修正后恢复识别，再等待模型。文字、置信度、语言、句段、供应商来源均一致才能复用预理解。提交前再次取得最新final，并保留题目、上下文、capture及owner围栏。
4. 准备语音期间仍持续接收新输入。新音频/字幕会取消旧模型或TTS等待，立即恢复倾听。只有可播放performance已选定，才进入播报防回声阶段；原插话协议继续生效。
5. 已批准动态表达经模型网关取得PCM，逐片送到LiveKit及浏览器AudioWorklet。候选端只播放计数PCM；RTC音轨用于房间录制，避免双播。已有完整题目资产仍优先复用。

## 对话与答案权限

`conversation_reception.v2` 在一次调用中返回种类、置信度、原文引用及最多180字的自然回应。集中Prompt/Schema及跨字段校验阻止额外字段、空回应和非法引用进入表达。它能处理未预设措辞、紧张、题意澄清、交流方式、补充更正及流程问题，但不能给技术答案、评分或代公司承诺。重复题目使用服务器冻结原题；公司事实不进入自由接话上下文。固定句仅为失败兜底。

提前理解只产生候选结果，不提交答案、不评分、不批准切题。新输入、换题、暂停、所有权变化及关闭撤销准备。如果提交前final才新增了话语，即使VAD/partial没提前报出来，也撤销旧口头确认和按钮结束许可，恢复倾听并重新判断。等待与紧张不会被当成完成回答。

公司反问抽取期间也继续识别；记录交流前重新校验完整final、原录音及所有权。公司回复保留来源引用，未提供资料时沿原未知答复，不杜撰企业事实。

## 可计数的流式播放

旧012实现使用 `MediaStream.currentTime`，供音暂停期间时钟仍前进，不能证明内容播放完成。052使用源样本计数和设备输出时钟，当前默认开启 `INTERVIEWER_STREAMING_TTS_ENABLED=true`。显式false可回到完整私有资产路径；不支持流式传输的供应商只允许首PCM前回退，已经播放后不自动整段重播。

媒体数据仅接收当前批准的publisher identity、`approved_expression`角色和output_id绑定。可靠数据包按序号、源样本偏移及采样率校验，有界2秒缓冲；欠载输出静音但不增加源消费计数。结束必须同时满足全部源样本已消费、服务端EOF已收到及 `getOutputTimestamp()` 越过末样本输出位置。缺片、超量、设备暂停、断线、换代或超时不伪造drained。协议详见[接口设计](api-design.md)。

## 验证证据

- 可控慢模型/合成音频覆盖：持续字幕、续说立即撤销、稳定预览复用、来源变化拒绝复用、提交前final修正及旧结束许可失效。新TTS准备测试只输入服务端PCM、不发浏览器起音信号，确认旧TTS未完成就被取消，所有续说帧仍进入同一capture。
- 真实已配置模型的14条合成交流请求全部通过，单次轻量模型调用1424–2195ms，中位数约1637ms。包含先讲思路、稍后更正、范围澄清、偏题拉回、引用“稍等”、公司未知及提示注入；这不是用户停止说话到听见回复的时间。
- 真实LiveKit与IAB Chromium：2秒PCM中间人为停供3秒，源时钟停在1000ms，恢复后到2000ms；末帧经过设备输出后才drain。正常流及6秒突发输入也保持精确样本数，不双播、不溢出。
- 正式压缩产物也在同一浏览器完成停供/恢复验证；另用实际minified worklet回归锁定类名绑定，避免开发源码正常、正式构建却无法启动音频线程。验证后已清理临时页面、端口和媒体房间。
- 真实现有TTS路由到同一浏览器播放：两次24字合成短句，从发起TTS请求到浏览器首次播放分别420.8ms、454.5ms；第一次首PCM390.0ms，首PCM后30.8ms播放，完整内容4.56秒；第二次完整内容4.24秒。这是小样本TTS阶段实测，未包含收音、STT、接话模型和新发布连接准备，不能称为整轮低于500ms或零延迟。
- 最终后端2212项通过、8项外部环境跳过，前端364项通过；正式资源、API和worker已加载本机，健康/就绪、资源hash和定时派发通过。维护前后原会话整体JSON摘要不变。全量回归、最终加载和失败过程追加在[操作日志052](change-log.md)。没有重放真实候选语音、创建业务面试或恢复原暂停会话。

## 仍有的限制

普通回答的保守补充等待策略仍存在；并行提前理解减少其后的等待，不等于取消所有静音时间。过渡语与问题拼接仍会重新合成，现可流式首播，尚未做分段复用全部过渡语和题目资产。没有承诺LLM token到TTS的未审批自由播报，也没有在听到半句话时提前切题。

真人长时中文、多口音、弱网、浏览器设备差异和足量有效轮次的端到端p50/p95仍需后续实测。G2P口型仍为估计。开发机器IP漂移另修正为当前网卡地址；这只修复本机RTC连通性，不能消除外部模型/网络时延。
