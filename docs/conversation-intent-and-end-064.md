## 上下文与语义边界

`conversation_input_context.v1`是纯投影：完整转写不修改，额外返回`current_speech/current_speech_start/responded_exchanges`。只验证本题选中的act、事件、序号、请求SHA256和精确唯一原文位置；最多六组。无法可靠定位（截断、ASR改写、重复短句等）保留全文。新话语为空时保留最后已回应请求供完整复核，不能因快接话选择了wait就把其误判当成事实。

`reception_exchanges`增加可选`kind`，既有JSON持久化无需DDL；旧条目无kind仍可提供角色关联。准备指纹包含这些回执、关联act内容及实际选中事件，新增回应会使过时准备失效。选中不等于声音已经送达，记忆不授予答案提交权限。

当前控制意图和累计技术证据分开：已回应概念问题只作背景；技术claims继续来自全文。明确结束当前回答、拒答当前题、结束整场各自独立。精确可识别的直接控制句只用于检测模型结果矛盾并触发原有一次纠正，不能直接生成结束许可。两次仍错返回结构化失败；否定、引用、假设、改口不能当成退出授权。所有Prompt、Schema和校验集中在`app/core/prompt/`。

版本：`semantic_turn.v15/v16`、`interview_turn_understanding.v40–45`、`interview_turn_decision.v71–76`、`conversation_reception.v6`；历史版本继续可读。v44/45与v75/76仅用于非语义模式已有可靠交流记录的理解路径，加入同样的当前发言范围而不授予新的完成许可。

## 结束状态与失败恢复

后续065已取代首次请求直接结束：现在必须独立二次确认。当前规范见[065说明](candidate-exit-confirmation-065.md)；以下保留064实现记录。

权威完整语音、有效模型理解和当前证据围栏通过后，沿既有`finish_on_candidate_intent / END_CANDIDATE_INPUT`提交结束。只说不会或回答完毕不能结束整场。输入完成与评分完成独立：已有答案继续评分，未考察范围明确保留，不伪造完整总分。

结束后停止收音/录制，告别与结束回执不等待评分。告别准备和录制停止使用有界等待，失败仍发送结束回执并释放本地owner；真实录制失败保留状态及审计，沿原人工恢复机制处理。输入已完成时媒体错误不能重新将会话暂停。重复结束、失效控制器和迟到输出仍受原幂等/所有权检查。

候选GET与控制快照返回安全`completion`投影；输入结束但评分仍在进行时，刷新同样直接展示结束回执。候选发布ticket拒绝重新授权采集，恢复控制连接不能重新attach收音owner，旧ticket的ready和媒体命令也不能重新打开输入。若断线期间结束而未收到completed，票据409只触发只读获取公共回执，不能重新申请采集权限。客户端完成后撤销重连与心跳，迟到的媒体初始化结果立即释放；麦克风和摄像头轨道清理不被媒体关闭异常跳过。

## LiveKit连接取消

独立适配器封装不可被取消的原生连接握手；调用方撤销、超时或失去权限立即停止等待，后台仅完成握手并disconnect，不创建音源或订阅候选音频。ingress在连接中被关闭时，迟到成功同样回收且不能重新报告connected。上游机制见[LiveKit Python SDK issue 784](https://github.com/livekit/python-sdks/issues/784)。

合成测试仅使用独立无音视频房间。本次不升级厂商SDK或修改原生依赖；正常进程退出与进程崩溃后的恢复仍是单独运维边界。
