# 试音确认后首题误暂停（061）

状态：verified（仓库回归、本机LiveKit合成及服务加载；真人听感/生产未验收）。此项只修复语音与会话控制生命周期，保留060语义理解、追问与可选定制。

## 实际故障证据

场次在11:45:06 UTC选中试音确认话语，11:45:07.524发布对应语音；11:45:12进入`preparing_next_topic`，11:45:12.568该表达参与者以`CLIENT_REQUEST_LEAVE`主动离开；同秒前端上报`AUDIO_TRACK_LOST`并持久暂停。正式turns/answers均为0。候选媒体断开出现在11:45:27，晚于该暂停，不能把后续离线当作起因。

试音字幕到达即可点击确认，这是合理交互。原服务端确认只启动录制、完成校准并开始规划，没有撤销仍在播放的试音话语。floor变化使旧输出授权失效；旧输出finally撤轨，runner因已失效不再报告错误，也没有通知前端取消。前端350毫秒的撤轨保护最终把该正常意图的停止当作故障。

## 修复合同

- 有效确认先按当前performance撤销并通知，再停止旧音频，随后启动正式录制并规划第一题。确认不要求用户等提示播完，也不创建第二条进入面试路径。
- 等待通知、清理或录制期间，暂停、校准重试和控制权变化使旧确认失效。前置/后置复核阻止迟到确认启动后续流程；录制失败仍阻止正式题目。
- managed试音重试在持久命令实际执行端撤销，继续补充同样先停止正在播放的输出；等待后复核原owner/control/capture/turn，不能改变后继话轮。
- 通用输出授权失效时，底层停止写入并清空队列，撤轨前发送该performance的取消通知。它只通知旧输出，不清除后继输出、floor或回答。
- 显式撤销与后台失效共享有界的精确通知，避免相互抢跑和重复消息。正常浏览器drained完成不误发取消；有效授权下供应商/传输失败继续进入真实故障处理，不以取消吞掉错误。
- 原PCM序号、240毫秒播放缓冲、首帧/播放超时、350毫秒异常撤轨检测及唯一drained回执保持。无新增用户填写、Prompt、模型调用或数据库迁移。
