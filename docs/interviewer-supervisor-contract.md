# 面试官总控实现合同（038 / 039）

总控位于现有InterviewAgentRuntime内部。当前题准备委派既有理解/追问专家，并注入有界跨题上下文、可选用户Skill和独立可选的企业资料索引；v3在awaiting_next_decision时调用总控选择新的冻结问题或结束考察。企业级要求属于Agent的可靠性和维护性，不要求用户提供企业身份或企业资料。

`InterviewerSupervisor.prepare_turn`返回严格理解与追问合同；`propose_next(session)`返回不可变NextInterviewDecision，绑定会话、decision_revision、contract/skill/company_context/agenda/证据指纹。指纹包含暂停、恢复和接管生命周期；单纯后台评分不会使下一话题提案失效。可信InterviewService在推理前和最终提交事务校验Evidence owner及控制连接ID/代数，提交时复核已选Skill授权、会话状态、时间预算及指纹后执行生命周期命令；模型不自行写库。

总控通过统一llm.chat_json、现有interview_turn_understanding route调用interviewer_supervisor.v2（039可选上下文合同）；interviewer_evidence_expert.v1继续提供无副作用的证据建议。输出只能包含action(select_question/finish_interview/use_tool)、question_id、inquiry_unit_id、tool_name、argument、reason_code和transition_key。所有字段必须存在，动作条件由领域校验；问题、短题单元ID与工具名使用本轮有限枚举，单元必须属于所选问题。模型可请求只读题库/经历/参考资料/证据覆盖专家工具，收到真实工具结果后继续决策；最多三次模型请求、两次工具调用、一次专家、十五秒共享期限。每次请求固定max_provider_retries=0、max_provider_attempts=1，主备目标不会暗中放大三次供应商尝试的上限，专家调用也计入共享预算。预算硬上限已到时服务端可以零次模型调用结束。超时或无效输出不产生选题或答案。

当前题首次final使用interview_turn_understanding.v12/interview_turn_decision.v11语义合同，分别记录answer_content与turn_intent。明确本题拒答或结束话题、结束整场必须绑定当前原文的completion_basis，不能伪造补充确认；已有技术内容照常保留claims。真实补充确认后的完整final使用interview_turn_understanding.v13/interview_turn_decision.v12：同样识别stop_interview，避免把“结束整场”降级为只换题。PreparedTurnDecision.completion_confirmed只保存服务端实际取得的确认权限，schema启用本身不授予完成权限。“没有补充”只结束本次回答，未明确关闭话题时仍可生成受约束的追问。两条路径均复核完整final身份、输入/上下文版本、capture及owner门；确认后新输入仍撤销旧结果。

039新增上下文版本只在semantic_first且interviewer_context含skill或company_context键时启用；两个键即使为空也表明采用可选上下文合同。旧调用无这些键时继续使用首次understanding.v10/decision.v9和确认后understanding.v11/decision.v10的原文与版本；旧非语义兼容路径不变。新增版本只改变上下文说明，响应schema、原文编号解析与语义权限校验保持一致，旧审计版本不被静默改写。

prepare_turn、prepare_preview与propose_next统一提供skill和company_context键。Skill含受信服务加载的instructions及reference_index，未选时不调用Skill冻结/授权/读取服务。新interview_skill.v2只要求name和自由文本/Markdown instructions，保存即active；旧enterprise_interview_skill.v1及已冻结enterprise_skill_snapshot继续兼容。Skill与企业资料四种组合均有效；均缺省时直接按岗位、题库、简历和实际交流面试，不追索企业资料或猜测企业事实。

企业资料由可选计划company_context文本冻结到session.plan_snapshot，同名输入最多12000字，空白归未提供。模型初始上下文只收到company_context={available:false}或{available:true,reference_id:"company:context"}，正文必须经company.read_reference("company:context")读取后才进入工具观察。Skill资源使用各自本地ID，与company:context隔离；个人Skill资源存在也可开放同一读取工具，但不表示提供了企业信息。无任何资源或企业资料时不公开该工具；已选Skill明确限制的工具权限继续生效。

表达承接从app/core/prompt下版本化、非评价性短句中选择，题目正文仍来自冻结快照。动态选择不接收新主问题或标准答案。用户Skill可以定制访谈方法与偏好，但不能覆盖平台schema、评分、结束依据、证据与权限。候选话语和参考资料只作为数据处理；工具不接受租户/凭据/文件URL参数。

v3追问的全场数量、每根问题数量及链深度统一取冻结assessment_contract预算：链深度等于获批的max_followups_per_root，最多允许三层。语义预检和生命周期提交使用同一预算，旧followup_policy缓存不能覆盖或扩大它；v2兼容路径继续保持原先数量和深度上限。新主话题仍由总控决定，追问只是当前根问题内受证据和预算约束的提案。

候选人只看到当前话题、已完成数量和准备/结束状态；不投影固定总题数、决策原因、工具轨迹、能力覆盖、Skill或企业资料正文。planning_problem只保留公开错误信息与retry_planning动作，planning.retry可重试。准备状态、失败状态及相应事件写入共用事务权限校验；过期owner或控制连接不得覆盖新状态或播报迟到错误。失败可恢复，重连从持久等待状态重新规划，同revision并发结果只有一个提交，已结束会话不会恢复选题。自然结束保留结束语期间的Evidence所有权，播放结束后只发一次completed收据。
