## 修改后的边界

- `question_for_repeat` 读取当前 turn 冻结题干；当前 turn 是子题时重读子题。旧 `dialogue_focus` 不再改变正式题锚点。
- `clarification_for_repeat` 只解析本题实际选中的解释焦点；明确要求重说解释时使用它，没有解释时回到当前题。不会从其他题捞取同名 act。
- `conversation_reception.v5` 分别接收 `current_question`、`root_question`、`last_clarification`、当前/根/父题 ID、角色历史、新发言与此前发言。历史最多16条，保持来源 ID，不能成为答案、公司事实或执行许可。
- `repeat_target` 为 `current_question` / `last_clarification` / null；只有 repeat 可非空。旧模型响应缺少该字段兼容默认当前题。仅在已判定 repeat 后，对未引用、未否定的明确重读目标做窄范围归一。
- 当前录音成功选择接话后才记录 `turn.reception_exchanges`，至多六组。记录候选请求尾部（最多1600字符）、原请求 SHA256、act ID、选中事件 ID/序号、时间和来源 stream ID。不保存新的完整录音或累计答案副本。
- 记录前复核组织、owner、capture、活跃题、状态、输入 guard、精确 performance 和选中事件；失败或过期跳过，不把后继回应接到旧请求上。预览不能写记录，取消清空暂存。可选记忆读写失败仅记录去敏错误类型，不能破坏已选播报、重开回声门或清除已处理游标；取消异常及核心所有权围栏仍保持。记录代表“被选择的回应”，不证明对方完整听到了音频。
- `recent_turn_dialogue` 依据选中事件把候选请求放在对应面试官回应前。持久化恢复后保留关系，仍不把这类记录伪装成评分用 utterance。
- 已回应游标与结束许可分离：麦克风活动可以撤销待提交决策，但不能把已处理的话变成新请求。真正新增的相同语句仍能回应；新 capture 不继承旧游标。
- 刷新连接沿用同一活跃 endpoint；STT 供应商恢复保留同一 final 前缀。owner 更换后含旧封存媒体的 capture 仍要求原恢复协议，不能仅凭聊天记忆恢复提交许可。
- 父题/子题独立回答、追问预算、评分证据引用、完成许可和输出撤销围栏保持。

没有新增公开 REST 入口或数据库表。已有 JSON turn 缺少新字段时按空历史读取，不回填、猜测或修订真实旧记录。

## 同场发现的其他故障

**语音等待：** 整场22次输出选择对应18个完成的 WAV 和4次取消。18个文件的字节数、SHA256与帧数均完整。一次约50秒的输出阶段由 **30.004秒首次打开超时 + 0.430秒重试打开 + 18.72秒语音** 组成，不能描述为音频文件内有50秒静音。此轮不修改 PCM 协议、缓冲或媒体分片，以免把上下文修复与音频调度混在一起。

**评分失败：** 前两份答案的评分供应商返回 HTTP 402。之前统一映射为 `provider_bad_request`，只显示配置错误。现在三个 OpenAI-compatible HTTP seam 统一给出 `provider_billing_required`，对外503、不可自动重试，审计保留402，模型页和评分页显示安全的计费/额度提示。400/401/429保持原分类，答案保留。实际账单问题需要管理员处理后从现有入口重评；本次没有充值、换路由或重评。

## 后续改进优先级

1. **P1：澄清内容的来源约束。** 将“术语定义”“题意重述”“解法提示”纳入多轮质量评测；必要时让定义来自可追溯词条，题意来自冻结题干。验收要求能解释概念，同时不列答案方案、不虚构考察重点。不能用全面拒答或大量关键词拦截代替自然交流。
2. **P1：TTS首次可播预算。** 依据真实首音分布缩短30秒首连阻塞，首 PCM 前的有限重试与故障提示分离；首 PCM 后不整段重播。用冷启动、限流、断流和打断场景验收，保持现有平滑播音。
3. **P1：交流送达状态。** 给每条交流记忆关联实际完成/被打断状态，让模型知道“已选择解释”和“对方听完解释”的差别；不得把供应商完成当成用户听完。
4. **P2：长期上下文回放集。** 固定覆盖20轮以上同题交流、子题切换、口误修正、长思考、静音、短确认、解释后完成和邀请追问；分开统计意图、循环率、无新话语触发率、问答关联和延迟，避免只用单句合同测试代表体验。
