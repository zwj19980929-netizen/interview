# 091：交流识别失败后的有限恢复

状态：in_progress。基线为4702859，实际验证和加载以[操作日志](change-log.md)为准。

## 现场证据

新场的服务端已有退出请求文字，但轻量接话在4秒超时后被缓存为有效other，并推进已读发言游标。候选端显式重试只重置了完整答案分析，原退出请求不再进入接话识别。后续完整分析先超时，随后返回不满足answer_unresolved联合约束的结果；原响应未保存，无法断言具体伴随字段错误。最终会话因预约窗口到期结束，不能再恢复为作答中。

## 恢复边界

失败与有效other分别处理。相同发言、阶段及已处理边界最多两次接话尝试；预览只能预计算，权威final仍须复核来源、当前capture和控制权后才能询问退出确认。成功结果与已经送达的交流历史保持缓存；纯音频活动、重复final和元数据变化不重新购买调用。

显式“重试处理”只重启尚未成功的可恢复接话，不清空成功历史，也不增加完整答案分析的原有调用额度。接话持续失败时仍允许原来的有界答案处理；鉴权等不可重试错误不自动循环。没有新公共恢复状态、Prompt或Schema，也不以关键词猜测退出。结束整场仍要求确认问题实际送达后的新权威确认回复。

调用启动时登记未完成来源，输入撤销和取消仍消耗尝试次数；同一发言两次被收音活动撤销后，自动重试停止，候选人显式重试才可重新识别当前权威发言。真正改口必须重新读取完整新发言；失去owner或媒体权限的错误不能续开旧控制。

## 同场录像收尾

已封存录像可能被较晚返回的StopEgress异常覆盖为failed：封存worker先完成，停止请求随后失败，旧逻辑读取最新记录后仍写入failed。修复只保护停止链的已完成/取消终态；完整性、来源绑定和存储保护校验不能因此跳过。历史错误审计保留，任何修复历史状态须重新通过真实封存校验。

## 已知环境缺口

该场断线后还触发批量转写修复，但当前只配置了真实流式STT；开发默认mock不能处理真实录音。这发生在最初重试之后，不是截图故障的起因。需要独立配置并验证支持stt.batch的真实模型，不能仅给现有流式型号增加能力声明。本项不借此修改候选发言、补交答案或虚构评分。

## 验证

覆盖首次接话超时后的自动恢复、显式重试、成功缓存、重复和失权边界，以及StopEgress挂起期间worker先完成、迟到停止失败的并发次序。合成验证不能证明真实供应商始终及时响应；完整回归和本机加载证据随后补充。
