# 073 · 补充确认与概念交流稳定性

## 两条独立故障

### 普通回答绕过补充确认

现场主答和追问都已提交，但对应轮次没有补充询问行为。模型将普通技术尾句作为 `finish_answer` 的依据；原合同只要求依据逐字存在于原文，没有证明该句确实授权交卷。运行时及最终提交服务都复用 `can_complete_without_confirmation`，因此模型判断直接触发追问或下一题。

产品约束：正常自然作答后，先询问是否还有补充，等实际播完后的新回复。模型的结束标签只能表示对当前发言的判断，不能代替补充确认。明确按钮、明确拒答/换题、已经实际澄清后的待核实收尾、独立整场退出各自保留原权限边界。

### 成功解释后的提醒被误计为回答处理失败

本场在 11:11:46、11:11:53、11:12:02 UTC 选择概念澄清回应，随后 TTS 成功，11:12:12 归还话权。11:12:13、11:12:24 已回应文字被去重；11:12:33 出现首次理解失败/重试耗尽。

本地合成复现确认：解释完成后，15秒空闲提醒仍继承前一次20秒理解期限。提醒实际调用语音之前就因旧期限已过而失败，上层误将该错误归入回答处理，显示“需要重试”。072的歧义修复没有覆盖这条路径。

11:14:17 另有一次 `reception_cannot_ask_question` 内容合同拒绝：接话生成包含不允许的新问句，不能据安全日志推断完整回复内容。它发生在首次重试提示之后，不是该提示的最初原因。接话失败仍须沿既有完整理解路径处理，不能直接制造答案或结束许可。

## 实现边界

- 正常 `answer/off_topic + finish_answer` 不能凭模型标签绕过补充确认；最终证据事务也检查同一规则，覆盖预处理、最终转写修正及直接服务入口。
- 补充询问的实际播放完成与新语音边界独立记录。播放中的话、仅有已选中记录、打断、超时或旧“没有”不等于确认；继续补充保留同一采集与原技术内容。
- 后续空闲提醒使用独立12秒期限，失败只记录固定诊断并消耗本次提醒机会，不增加回答理解失败次数、不重置正式理解期限。取消、过时结果和所有权失效仍向上传递。
- 普通回答与概念解释、内容疑点澄清、明确不会、换题及整场退出分别处理。纯概念提问不是技术答案；结束整场仍走独立二次确认。
- 补充答复分类合同没有整场退出枚举。不确定答复在当前语义模式下最多复核一次完整意图，将退出/关闭话题等交给既有门禁；普通答案不能从复核递归进入同一补充分类。已播放补充询问不能替代退出询问，接受和拒绝退出各有真实合成音频链路验证。
- 真实历史答案、录音、评分不重写；本次不将本地合成回归描述为真人或外部供应商验收。

## 验收场景

| 场景 | 必须保持的行为 |
| --- | --- |
| 技术回答，模型误标结束 | 先问补充，不直接提交、追问或换题 |
| 正常说“我说完了” | 完成补充确认流程 |
| 问题尚未播完或被打断时说“没有” | 不形成补充确认 |
| 问题实际播完后明确无补充 | 同一回答提交一次 |
| 明确继续补充，再表示结束 | 保留原答案和新增内容，不反复开启相同询问 |
| 概念解释后长时间沉默 | 提醒有界，不显示回答处理失败，不提交答案 |
| 可选提醒超时 | 继续保留采集，失败不污染回答准备状态 |
| 明确不会、换题或提前结束按钮 | 保持对应明确控制路径 |
| 补充确认时明确结束整场 | 正式理解后进入独立退出确认；新回复接受才退出，拒绝则继续 |
| 最终转写出现新内容、所有权变化 | 撤销旧确认/过时输出，不越权提交 |
