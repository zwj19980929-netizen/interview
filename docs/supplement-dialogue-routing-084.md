## 模块边界与状态迁移

`SpokenSupplementConfirmation` 对实际送达补充问题后的权威新回复，调用一次 `supplement_reply.v6`。中央合同只输出交流意图、置信度、当前话语证据及有界回复，不生成评分理解或结束依据。它获得当前题、根题、候选可见历史和最近已送达话语，并带服务端reply_target（supplement_question/other_delivered_speech/unknown），以区分对补充问题的回答与对刚才解释的回应；历史question不是当前确认对象，孤立附和不能结束。旧答案不是当前许可。

- 提问、重读、题意解释、一般交流、声音问题、转写纠正、等待：进入既有非提交接话，保留整段录音和回答。
- `unclear` 或低置信度：询问候选人意愿，保持当前题开放，不自动触发完整分析。
- 跑题：引回当前题；不把此前正常技术回答整体标为跑题。
- 继续或新增补充：继续听取同一capture。
- `finish`：沿现有确认和receipt规则；有新增技术内容或来源变化时仍须分析完整证据。
- 结束题目、拒答：进入原完整理解和领域校验，不能把小合同结果当作完成依据。
- 退出整场：只发起独立退出确认；必须实际送达后取得新的明确回复。
- 公司问题：保留现有完整证据和公司资料问答路径，不使用轻量模型编造公司事实。

退出及针对内容歧义的澄清保留自己的处理路径。预览不能形成补充确认，也不再为同一补充回复提前调用接话模型。分类使用完整final和boundary来源，在等待后核对capture、所有权和语境。正式分类开始前还要求实际stage为awaiting_reply、final与识别器现有final全字段一致，不能只相信本地已送达旗标。模型输出仍由统一Schema与业务证据规则校验，未知字段、错误类型、非法枚举或不合法证据不会被直接使用。
